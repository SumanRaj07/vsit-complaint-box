# VSIT Complaint Box — Supabase Setup (OPTIONAL — NOT NEEDED)

> **The app runs 100% locally and never uses Supabase.** This folder is kept
> only as reference SQL in case the college ever wants a cloud backend.
> Do NOT follow these steps to run the app — just install the APK or open
> the web build.

If the college later decides to move to the cloud, follow these steps **in order**.
The whole setup takes about 15 minutes. You need only a free Supabase account
— no card required.

## 1. Create the Supabase project

1. Go to https://supabase.com and sign in (or create a free account).
2. Click **New project**.
3. Name: `vsit-complaint-box`. Choose any database password and **save it**.
4. Region: choose the one nearest to you (e.g. Mumbai / Singapore).
5. Click **Create new project** and wait 1–2 minutes.

## 2. Run the database migrations

1. In the Supabase dashboard, open **SQL Editor** (left sidebar).
2. Click **New query**.
3. Open the file `supabase/migrations/0001_init.sql` from this project,
   copy its **entire contents**, paste into the SQL Editor, and click **Run**.
   Wait for "Success. No rows returned".
4. Repeat with `supabase/migrations/0002_seed.sql` (departments + FAQs).

> If you see an error, read it carefully — it usually names the exact line.
> The most common cause is running `0002` before `0001`.

## 3. Create the demo accounts (optional, for evaluation)

1. Go to **Authentication → Users → Add user**.
2. Create these four users (use **Auto Confirm User** so no email is needed):

   | Role | Email | Password | College ID |
   |---|---|---|---|
   | Student | student@demo.vsit.edu | Demo@1234 | VSIT2026001 |
   | Teaching Staff | staff@demo.vsit.edu | Demo@1234 | EMP1001 |
   | Dept Officer | officer@demo.vsit.edu | Demo@1234 | EMP2001 |
   | Super Admin / HOD | admin@demo.vsit.edu | Demo@1234 | EMP9001 |

3. After creating each user, click the user in the list and **copy its UUID**.
4. In `0002_seed.sql`, uncomment the "demo profiles" block, replace the
   `<STUDENT_UUID>` etc. placeholders with the real UUIDs, and run that block
   in the SQL Editor. (Staff accounts are created with `pending_approval`
   only when a staff member self-registers; demo staff here is pre-approved.)

> **Never** put real passwords in the app code. These demo passwords exist only
> in this document so an evaluator can log in.

## 4. Connect the Flutter app (only if moving to the cloud)

> This requires code changes: the current app has no Supabase client.
> The SQL in this folder defines the schema, RLS policies and the
> `track_anonymous()` function; a Supabase repository would need to be written
> against the same `ComplaintRepository` interface the app already uses
> (`lib/data/repository.dart`).

1. In Supabase, go to **Project Settings → API**.
2. Copy the **Project URL** and the **anon / public key**.
3. Keep the **service_role key secret** — it must never be used by the app.

## 5. What is created

- **Tables:** profiles, departments, complaints, complaint_attachments,
  complaint_updates, complaint_messages, notifications, feedback, audit_logs,
  app_settings, faqs, suggestions.
- **Storage bucket:** `complaint-evidence` (private; evidence files).
- **Row Level Security:** students see only their own complaints, department
  officers see only their department's complaints, Super Admin sees all.
  Anonymous complaints are tracked through the `track_anonymous()` function,
  which never returns identity fields.
- **Tracking IDs:** `VSIT-YYYY-NNNN`, generated by `next_tracking_id()`.

## 6. Going live for the college

1. Replace the demo accounts with real staff accounts (register in the app,
   then approve them from the Super Admin → User Management screen).
2. In **Authentication → URL Configuration**, set the Site URL to your web
   app's deployed URL.
3. In **Authentication → Email Templates**, enable email confirmation if you
   want verified student emails.
4. Keep the **service_role key secret** — it is never used by the app.
